# Use host-adaptive artifact delivery

Profiles define the Agent Profile Kit material a managed session receives, but an Adapter may deliver each artifact category through a different native Host mechanism. Prefer process-scoped inputs; when a Host cannot discover an artifact per process, an Adapter may maintain an explicitly owned shared projection and apply process-scoped selection over that projection. The projection is disposable output, never canonical source, and must not adopt, overwrite, disable, or remove unrelated Host material.

For Claude Code, Context uses an appended system-prompt file and Skills use an additional directory containing the Profile Installation's `.claude/skills/`; generated plugins remain optional for artifact categories that benefit from them. For Codex, the Adapter projects every Workspace Skill into the dedicated `~/.agents/skills/agent-profile-kit/` Skill Library and passes a process-only `skills.config` override that enables the selected Agent Profile Kit Skills and disables the unselected ones. It never writes Codex configuration. Ordinary unmanaged Codex launches can therefore discover the complete Workspace Skill catalog, while managed launches preserve Profile selection semantics.

The Codex Skill Library has its own ownership Manifest, whole-tree hash, transactional replacement, freshness reporting, and lifecycle. Immutable library generations live under Agent Profile Kit state, while an atomically replaced symlink at the standard Codex discovery path selects the current generation without a missing-library window. Managed runs pin their resolved generation and hold a kernel-backed lease until the native Codex process exits. A macOS `lockf` lifecycle lock serializes generation publication, leases, Profile publication, dependency enumeration, and removal; kernel locks release automatically if a process crashes and therefore need no stale-lock deletion protocol. Agent Profile Kit refuses an existing unowned destination or a conflicting Skill identity before writing. The library remains while any installed Codex Profile or active managed run depends on it and is removed only when its Manifest proves ownership. Final uninstall fails while a run is active and prunes lease files proven unlocked after a terminated wrapper or native process.

This supersedes ADR-0003 only where it required every artifact itself to be delivered through a process-scoped path; semantic Profile selection and concurrent isolation remain required. It supersedes ADR-0004 only where it prohibited all shared global output and required each Profile Installation to contain every artifact; self-contained Profile Installations remain the default.
