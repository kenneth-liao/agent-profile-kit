# Record the ownership reduction to match generated-output disposability

Agent Profile Kit generates disposable, deterministically reproducible material into Projects, but for most of its life it guarded that output with proof-of-ownership discipline appropriate for irreplaceable user data. Two structural causes produced a class of permanent dead ends: ownership was stored in two places (an Installation Receipt in machine-global Installation State *and* an Installation Marker inside the Project), and a design trade made in ADR-0004 was reversed by ADR-0010 without being re-argued, returning the path-level ownership machinery ADR-0004 had deliberately declined. Ordinary user actions — deleting a Project's generated files, emptying `.git/info/exclude`, uninstalling an Agent Host — wedged fleets behind Blockers whose remedies asked users to restore internal bookkeeping they had never been told about (spec #371).

This record states the accepted reduction and supersedes the decisions it replaces, so the rationale has a single home rather than being reconstructed from the nine tickets that delivered it (#374–#382).

## Decision

- **The Installation Receipt in Installation State is the single canonical home for Profile Installation ownership.** The Installation Marker — its schema type, path constant, and every read, write, comparison, and identity check — is removed from the Installer, Adapters, and schemas. Ownership authority is an active Installation Receipt naming a canonical Project whose recorded output paths are safe; freshness continues to derive from recorded content hashes. Ownership continuity requires either at least one extant recorded root matching its recorded hash, or every recorded root wholly absent; the all-absent case authorizes ordinary restoration and cannot distinguish a replacement Project at the same path — accepted, because the material is regenerable from the Workspace and the Project Binding owns the canonical path. Changed extant roots with no matching recorded hash are the fail-closed case: they cannot be distinguished from a different Project later created at the same path, so they are never adopted, refreshed, or removed. A copied or moved Project is handled by Project Binding scope alone: a directory that is not the canonical Project of an active binding is never inspected, planned, or written, and no copy or relocation detection exists. `unbind` retires the Project's active Installation Receipt in the same operation, so no active receipt outlives its binding; the retired record keeps exactly the detail the active receipt recorded and persists as the sole teardown authority until the next `apply` consumes it, and `uninstall` proceeds per Project, never letting one Project's unremovable output block another's teardown.
- **Repository Exclusion Contribution is derived, best-effort bookkeeping — a cache, not durable ownership evidence.** `apply` rewrites the Agent Profile Kit-owned section of each exclusion target derived from the active receipts at write time, preserving unrelated bytes; a missing, stale, or modified section is overwritten rather than proven. Exclusion state can never produce a Blocker: any failure to read, derive, or write a target produces one warning and does not affect the outcome of the installation. Receipts stopped recording an exclusion target and entry list, the exclusion Blocker kinds are removed, and the exclusion Safe Repair classes and their transactional staging are deleted with no rollback — a superseded or failed write self-heals on the next `apply`.
- **Safe Repair as a separate authority boundary is removed.** ADR-0022's exhaustive typed repair boundary, its eligibility gates, and its distinct presentation seam are deleted. Restoring absent owned output is ordinary pending work that `status` reports and `apply` performs, planned from the receipt and the Workspace like any other write. Whole-root replacement from current Workspace source, never member-level merging, remains the refresh rule.
- **Agent Host capability probing is advisory.** Probe results classify Host capability for warning purposes only: they never gate planning, never gate writing, and never produce a Blocker. Deduplication is one warning per Host per invocation for a missing or outdated Host CLI, naming the Host and its required version, regardless of how many Projects select the Host and how many distinct requirement messages it produced; Project-specific surface failures (an occupied Host surface on one Project, for example) keep their distinct warnings per affected Project. Output is written regardless. `status` performs no Agent Host process execution; probing happens only during `apply` (and temporary installation), and its failure is never fatal. Adapters remain the sole authors of that requirement.
- **Blockers and Installer errors are typed facts with no user-facing sentence.** The Installer emits kind, affected Project, affected paths, and affected Host, with no `problem`, `requirement`, or `remedy` prose. Presentation (`cli/blocker-wording.ts`) is the single home of every user-facing sentence, keyed by the typed `BlockerKind`; the machine JSON publishes the stored wording verbatim. The closed kind vocabulary and the loud rejection of malformed evidence are unchanged from ADR-0016; only the prose-carrying record shape is superseded. The residual Blocker vocabulary is exactly the set that cannot be a warning: Git-tracked generated paths and other output ownership conflicts, occupied unowned destinations, unprovable or unsafe ownership and removal authority, unreadable Installation State, and temporary-installation conflicts.
- **ADR-0004's disposability rationale is restored.** ADR-0004 accepted duplicated generated artifacts "in exchange for avoiding global writes, symlinks, immutable generations, background synchronization, and path-level ownership machinery." ADR-0010's Project-bound installation retained the project binding but returned the path-level ownership machinery; this record removes that machinery again while keeping Project-bound delivery. Generated material is regenerated confidently from the Workspace, and Agent Profile Kit treats its own bookkeeping as a cache rather than as durable evidence.

Failure modes that previously produced Blockers are now warnings the user can ignore, self-healing conditions `apply` resolves without being asked, or states that no longer exist because the state that produced them was removed.

## Consequences

The two unrecoverable dead ends stop existing: deleting a Project's generated files leaves ordinary pending work, and altering or deleting `.git/info/exclude` is never Agent Profile Kit's business to police. `status` cannot fail because another product's CLI is absent from `PATH`, and uninstalling an Agent Host no longer wedges a fleet.

Agent Profile Kit no longer detects that a Project directory was copied or relocated with its generated files intact, and no longer refuses to act when the Repository Exclusion Contribution has been altered. Both are accepted: the material is regenerable from the Workspace, out-of-binding directories are never touched, and the exclusion section is a convenience. The identity boundary is correspondingly narrower: an active receipt whose recorded output paths are safe is the whole ownership proof. Changed extant roots with no matching recorded hash fail closed rather than being adopted, while wholly absent roots authorize ordinary restoration without distinguishing a replacement Project at the same path.

The machine contract carries the reduction visibly: removed Blocker kinds disappear from the versioned JSON enumeration, warnings gain the Host capability and exclusion cases, and exit-code meanings are unchanged (0 clean, 1 tool error, 2 Blockers present). Vocabulary for deleted concepts — Installation Marker and Safe Repair — is removed from the product and the glossary rather than hidden behind a term list.

## Supersessions

This record supersedes **ADR-0022 in full**: the Safe Repair authority boundary, its eligibility gates, and its distinct presentation seam no longer exist; restoration of absent owned output is ordinary `apply` work planned like any other write. It supersedes the **ownership-evidence portions of ADR-0019** — the Installation Marker as the project-travelling token linking a Project to a receipt identity, the active receipt's recorded Repository Exclusion Contribution as ownership evidence, and Host capability gating before writes — while ADR-0019's remaining boundaries (one strict deterministic JSON state document, receipt shape, aggregate-hash freshness, atomic publication) remain in force. It supersedes the **prose-carrying typed-blocker boundary in ADR-0016**: since #382, Blockers are exhaustively typed records carrying facts only, and presentation owns every user-facing sentence keyed by the typed kind; the closed vocabularies and loud rejection of malformed evidence are unchanged. ADR-0016's terminal-presentation boundary, read-only discovery boundary, and the rest of ADR-0019 are unaffected. It also supersedes **ADR-0010's recording-only `unbind` state boundary**: since #375, `unbind` also retires the Project's active ordinary Installation Receipt in the same operation, while never removing generated output and leaving `bind` recording-only.

For provenance, the kinds ADR-0023 published — the Repository Exclusion Contribution blocker family — are among those this reduction removed from the typed Blocker class; that record remains a historical account of its delivery.

The maintained glossary (`CONTEXT.md`) owns the canonical Blocker definition; `docs/ARCHITECTURE.md` owns the reduced structural facts.
